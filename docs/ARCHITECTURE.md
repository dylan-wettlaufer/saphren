# Saphren v0.1 Architecture

Saphren uses a **headless Rust core** paired with a **thin Tauri v2 + React UI shell**. All workspace state, file watching, diffing, conflict detection, and MCP protocol logic live in pure Rust crates with zero UI dependencies.

## 1. Repository & Crate Layout

```text
saphren/
├── Cargo.toml                 # Cargo workspace root
├── .gitattributes             # Marks src/bindings.ts as linguist-generated
├── docs/                      # Planning vault (specs, architecture, wireframes)
├── crates/
│   ├── saphren-core/          # Headless domain: sandbox, file I/O, watcher, diffs, proposals
│   └── saphren-mcp/           # Local MCP server (rmcp + axum) exposing 4 workspace tools
├── src-tauri/                 # Thin Tauri v2 bridge: commands, event forwarding, app lifecycle
└── src/                       # Thin React + TypeScript + Tailwind renderer (zero business logic)
    └── bindings.ts            # Auto-generated by tauri-specta
```

### Dependency Direction

- `saphren-core` depends on nothing else in the workspace.
- `saphren-mcp` depends on `saphren-core`.
- `src-tauri` depends on `saphren-core` and `saphren-mcp`, wires them together at startup, and forwards core events to the frontend.
- `src/` calls Rust exclusively through generated `tauri-specta` commands and listens to typed Tauri events.

## 2. Core Domain (`saphren-core`)

### Workspace Sandbox

- Every path passed by the UI or an MCP client is resolved relative to `workspace_root`, canonicalized, and verified with `starts_with(&workspace_root)`.
- Any path traversal attempt (e.g., `../`) or symlink escaping the root returns `WorkspaceError::PathOutsideRoot`.

### Core Data Types

- **`WorkspaceState`** (protected behind `Arc<RwLock<...>>` or an actor loop):
    - `root: Option<PathBuf>`
    - `open_file: Option<OpenFileBuffer>` (tracks the active file's relative path, live unsaved text, `disk_hash`, and `is_dirty`)
    - `proposals: HashMap<ProposalId, PendingChange>` (keyed by UUID; at most one active pending proposal per file path in v0.1, or latest replaces prior)
- **`PendingChange`**:
    - `id: String`
    - `path: String` (relative to workspace root)
    - `base_hash: String` (SHA-256 of the content the proposal was generated against)
    - `proposed_content: String`
    - `reason: String`
    - `diff_lines: Vec<DiffLine>` (computed via the `similar` crate: `Context`, `Added`, `Removed`)
    - `created_at: String` (ISO-8601)

### State Machines

**Active File Lifecycle**

- `Clean` → user types → `Dirty`
- `Dirty` → user hits `Cmd/Ctrl+S` → `Clean` (writes to disk, updates `disk_hash`)
- `Clean` → `notify` detects external disk edit → silently reloads buffer and emits `FileReloaded`
- `Dirty` → `notify` detects external disk edit → `ExternalConflict` (UI prompts Reload vs. Keep Local)

**Proposal Lifecycle**

- Agent calls `propose_edit` → `Pending` (emits `ProposalCreated`; disk untouched)
- User clicks **Reject** → `Rejected` (removed from queue; disk and buffer untouched)
- User clicks **Accept**:
    - If current content hash equals `base_hash` → writes `proposed_content` to disk, updates open buffer if active, removes proposal → `Accepted`
    - If current content hash differs from `base_hash` → returns `Conflicted` state (UI shows Keep My Edits vs. Overwrite with Proposal)

## 3. Local MCP Server (`saphren-mcp`)

- **Transport:** Streamable HTTP (`rmcp` with `transport-streamable-http-server` mounted on `axum`) listening on `http://127.0.0.1:4721/mcp` (falls back to an ephemeral port if `4721` is occupied).
- **Session Management:** In-memory `LocalSessionManager` so external CLI agents (Claude Code, Codex, Gemini CLI) can connect concurrently to the running desktop app.
- **Write Safety Rule:** MCP tools **never** write directly to disk. All edits go through `propose_edit`
### v0.1 Tool Contract

|**Tool**|**Input JSON**|**Output JSON**|**Notes**|
|---|---|---|---|
|`list_files`|`{ "subpath"?: string }`|`{ "files": string[] }`|Lists `.md` files relative to workspace root|
|`read_file`|`{ "path": string }`|`{ "path": string, "content": string, "is_dirty": bool }`|Reads live in-memory buffer if file is currently open, else disk|
|`search_files`|`{ "query": string }`|`{ "matches": [{ "path", "line", "snippet" }] }`|Case-insensitive substring search across `.md` files|
|`propose_edit`|`{ "path": string, "new_content": string, "reason": string }`|`{ "proposal_id": string, "status": "pending_review" }`|Computes diff, queues `PendingChange`, emits UI event|
## 4. Tauri v2 IPC Contract (`src-tauri` <-> `src/`)

All commands and event payloads derive `serde::Serialize`, `serde::Deserialize`, and `specta::Type` so `tauri-specta` auto-generates `src/bindings.ts` in debug builds.

### Commands (UI → Rust)

- `open_workspace(path: String) -> Result<WorkspaceSnapshot, AppError>`
- `open_file(path: String) -> Result<OpenFileView, AppError>`
- `update_buffer(path: String, content: String) -> Result<(), AppError>` _(syncs live editor text to core so MCP `read_file` sees unsaved edits)_
- `save_active_file() -> Result<(), AppError>`
- `accept_proposal(id: String, force_overwrite: bool) -> Result<AcceptResult, AppError>`
- `reject_proposal(id: String) -> Result<(), AppError>`
- `accept_all_proposals() -> Result<BatchAcceptResult, AppError>`
- `get_mcp_status() -> McpStatus` _(returns `{ running, url }`)_


### Events (Rust → UI)

- `workspace_tree_updated` — file created, renamed, or deleted on disk
- `file_reloaded` / `file_external_conflict` — external disk change on the open file
- `proposal_created` — triggers blue dot in file tree and enables review banner
- `proposal_resolved` — clears blue dot after Accept or Reject

## 5. Architecture Decision Records (ADRs)

- **ADR-001: Headless Rust Core + Thin Tauri v2 Shell**
    - _Why:_ Keeps Rust as the primary language and enables a fast, cross-platform v0.1 with React + Tailwind (and Excalidraw in v0.2), while allowing a future GPUI frontend swap without rewriting core or MCP logic.
- **ADR-002: Staged Writes Only via MCP**
    - _Why:_ Enforces the human-directed principle and prevents race conditions when the user has unsaved edits in the active buffer.
- **ADR-003: Streamable HTTP over Stdio for Local MCP**
    - _Why:_ External CLI agents need to connect to an already-running Saphren desktop window rather than spawning a separate headless child process per agent.
- **ADR-004: File-Level Proposal Acceptance in v0.1**
    - _Why:_ Avoids partial-hunk patch reconciliation complexity in v0.1; per-hunk acceptance moves to v0.2.
