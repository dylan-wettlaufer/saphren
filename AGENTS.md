# AGENTS.md

Saphren is a local-first desktop workspace for writing Markdown alongside AI agents.
Read `docs/v0.1-spec.md` and `docs/architecture.md` before making architectural or scope decisions.

## Repo Layout
- `crates/saphren-core/` — Headless Rust domain (workspace sandbox, file I/O, `notify` watcher, `similar` diffs, proposal state). Zero UI or Tauri dependencies.
- `crates/saphren-mcp/` — Local Streamable HTTP MCP server (`rmcp` + `axum`). Depends only on `saphren-core`.
- `src-tauri/` — Thin Tauri v2 IPC bridge (commands, events, app lifecycle).
- `src/` — Thin React + TypeScript + Tailwind renderer.

## Hard Architectural Rules
1. **Keep the frontend dumb:** Never implement diffing, hashing, conflict detection, or filesystem logic in `src/`. All domain logic belongs in `saphren-core`.
2. **Never hand-edit `src/bindings.ts`:** It is auto-generated by `tauri-specta` from Rust types and commands.
3. **No direct disk writes from MCP:** `saphren-mcp` tools must never write to disk. All edits go through `propose_edit` and require explicit user approval.
4. **Enforce the workspace sandbox:** Every file path must be resolved relative to `workspace_root`, canonicalized, and verified with `starts_with(&workspace_root)`.
5. **Respect v0.1 scope:** Do not add tabs, WYSIWYG/Live Preview, per-hunk diffing, ACP chat, or canvas features unless explicitly requested.

## Verification
Run relevant checks before finishing a task:
- Rust tests: `cargo test --workspace`
- Rust lint: `cargo clippy --workspace --all-targets -- -D warnings`
- Frontend typecheck: `npx tsc --noEmit`

## Git & Conventional Commits
All commit messages **must** strictly follow [Conventional Commits](https://www.conventionalcommits.org/).

**Format:** `<type>(<scope>): <imperative summary>`

- **Allowed types:** `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `style`, `perf`, `ci`
- **Recommended scopes:** `core`, `mcp`, `tauri`, `ui`, `docs`, `deps` (optional if repo-wide)
- **Rules:**
  - Lowercase type and scope, imperative mood, no trailing period, max ~72 chars on the subject line.
  - Keep commits atomic—one logical change per commit.

**Examples:**
- `feat(core): add workspace path sandbox validation`
- `feat(mcp): implement propose_edit tool over streamable http`
- `fix(ui): prevent conflict banner flicker on buffer sync`
- `test(core): cover dirty buffer conflict on proposal accept`
- `docs: add v0.1 spec and architecture`
